NET-005 — Routing and Path Selection Findings

Baseline:
10.10.20.10 matched connected route 10.10.20.0/24.
Selected interface: enp0s20f0u3u3c2
Selected source: 10.10.20.101

1.1.1.1 initially matched two default routes.
Wi-Fi default metric: 600
Lab Ethernet default metric: 20100
Selected path: via 192.168.1.1 dev wlo1
Selected source: 192.168.1.3

Longest-Prefix Test:
Temporary route:
1.1.1.1/32 via 10.10.20.1 dev enp0s20f0u3u3c2

Result:
The /32 route overrode both /0 default routes despite the Wi-Fi default having the lower metric.

Packet Validation:
tcpdump on enp0s20f0u3u3c2 observed ICMP echo requests:
10.10.20.101 -> 1.1.1.1

Failure-Diagnosis Test:
Temporary route:
203.0.113.10/32 via 10.10.20.1 dev enp0s20f0u3u3c2

The configured next hop 10.10.20.1 was REACHABLE at Layer 2.
The real next-hop MAC is redacted from public evidence as [ER605-MAC].

Two ICMP echo requests were transmitted.
No echo replies were received.

Conclusion:
A valid local route and reachable next hop do not prove end-to-end reachability.
Route selection was demonstrated locally. The absence of return traffic does not localize a failure: 203.0.113.10 is a documentation address (RFC 5737) and lab traffic to the internet is blocked by DENY_Lab_to_Any, so no reply was expected. (Corrected October 5, 2026.)

Restoration:
Temporary /32 routes were removed.
1.1.1.1 and 203.0.113.10 returned to the Wi-Fi default route.
